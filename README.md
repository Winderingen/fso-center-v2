# Справочно-экзаменационная система Управления ФСО РФ по АФО

created by Miklosh Bulava

Самостоятельный комплект для **нового** репозитория GitHub и **нового** проекта Supabase. Версия API: `2026-10-17-new.1`. Старые настройки, база и импортированные кодексы не включены.

**Первый запуск через браузер: [SETUP.md](SETUP.md).** Выполните шаги по порядку; Windows Git, Node.js, Docker и Codespaces для публикации не нужны. GitHub Actions запускает необходимые инструменты в своём окружении.

## Возможности

- Законодательство по кодексам, сворачиваемым разделам, статьям и подпунктам; важные статьи закрепляются сверху.
- Отдельный устав и инструкции с изображениями; редактирование из справочника, черновики и защита от случайного закрытия формы.
- Структура организации: руководство, управления, отделы, должностные лица и удостоверения.
- Банк вопросов по категориям: один ответ, несколько ответов, соответствие, порядок действий.
- Экзамены по отделам СБП / АС / Академия / КМК; ручная и случайная компоновка, перемешивание вопросов; тренировочные тесты по одной теме.
- Допуск к экзамену по кодовому слову, ФИО, званию и удостоверению `123-456`; необязательные ФИО и жетон инструктора.
- Курсанту после завершения виден только процент; разбор ответов доступен администратору.
- Администратор видит результаты, фильтры, статистику и CSV; может завершить попытку, удалить результат или завершить и удалить активную попытку.
- Изображения загружаются и сохраняются в базе вместе с документом/вопросом; текущий лимит файла 450 КБ, запроса 2 МБ.

Закрытие браузера не используется как гарантированный сигнал завершения. Зависшую попытку можно завершить администратором; истёкшие попытки также закрываются при очередном обращении к серверу.

## Публикация

В проекте один workflow **Publish FSO Center**:

1. проверяет тесты;
2. создаёт публичный config.js из переменных нового репозитория;
3. разворачивает fso-api в выбранный новый Supabase;
4. проверяет опубликованную версию API и поддерживаемые возможности;
5. публикует папку site на GitHub Pages.

Если API не соответствует комплекту, публикация нового интерфейса останавливается. В старом и новом репозитории не нужно смешивать файлы разных пакетов.

## Основные файлы

| Путь | Назначение |
|---|---|
| site/ | Интерфейс, стили, изображения |
| supabase/setup.sql | Однократное создание схемы и начального наполнения нового проекта |
| supabase/functions/fso-api/index.ts | HTTP, Supabase Auth и транзакции |
| supabase/functions/_shared/domain.mjs | Вопросы, экзамены, результаты, права администратора |

| scripts/build-config.mjs | Создание публичной конфигурации |
| scripts/check-live.mjs | Проверка работающего API после развёртывания |
| tests/ | Проверки логики, HTTP, сохранения и публикации |

## Локальный запуск — необязательно

С установленным Node.js 22.13+ (рекомендуется 24):

```text
npm test
npm start
```

Адрес: http://127.0.0.1:4173. Начальные **локальные** реквизиты: admin / FsoDemo2026!, код пробного экзамена АКАДЕМИЯ. Они не создают администратора в Supabase. Локальная база находится в .runtime и не включена в комплект. В исходном site/config.js оставлен local для локального запуска; Actions автоматически создаёт supabase-конфигурацию при публикации.

## Данные первого облачного запуска

Есть учебные заглушки материалов, три простых вопроса и примеры остальных форматов в банке. Правильный шаблон удостоверения в учебном вопросе — `123-456`. Тренировочный тест открыт. Пробный экзамен создан **черновиком без заранее заданного кода**: администратор должен сгенерировать код и сохранить публикацию через сайт. Результатов сотрудников и импортированных нормативных документов нет.

Для повторной генерации setup.sql при разработке используйте `node scripts/prepare-setup-sql.mjs`; для обычного первого запуска готовый файл уже включён. Не выполняйте начальную инициализацию вместо резервного копирования существующего проекта.
